# Study Agent 产品设计方向基线

> 文档类型：产品设计决策 / GrillMe 阶段基线  
> 状态：已锁定方向，后续实现与 PRD 整理应以此为上位约束  
> 更新时间：2026-08-07  
> 适用范围：统一 React 产品前端、学习任务系统、角色与群聊、学习状态、主动性策略、Lab 信息架构

---

## 1. 产品定位

### 1.1 一级定位

Study Agent 首先是一个**学习产品**，不是 AI Agent 控制台。

用户进入产品后的第一目标应当是：

> 继续学习，而不是检查系统。

因此，模型路由、Provider 健康、Token/成本、RAG 调试、工作流事件、详细性能指标、安全模式细节等系统能力，不应与核心学习流程竞争一级界面注意力。

### 1.2 Lab 定位

Lab 作为**二级入口**保留完整工程可观察性与高级控制能力。

普通学习界面只暴露用户理解当前学习结果所必需的信息，例如：

- 已参考若干资料；
- 当前内容来自哪个学习任务；
- 当前建议下一步；
- 必要的错误或降级提示。

高级信息进入 Lab，例如：

- 模型与路由详情；
- Provider 状态；
- Token 与成本；
- RAG 检索与召回细节；
- 工作流事件；
- 性能指标；
- 调试和强制覆盖设置。

核心原则：

> **开发者可观察性 ≠ 学习者主界面信息架构。**

---

## 2. 核心产品对象：Learning Task

### 2.1 Conversation 不再是核心对象

聊天是主要交互方式，但不是产品的核心工作对象。

Study Agent 的核心对象提升为：

> **Learning Task / 学习任务。**

Learning Task 表示一个**可完成、可验证的学习目标**，而不是学科、标签或聊天主题。

不推荐：

- Java
- 数学
- Spring
- Study Agent

推荐：

- 理解 Spring 事务为什么会失效；
- 学会曲边区域二重积分如何确定积分限；
- 看懂 Study Agent 的 RAG 检索链路；
- 能独立解释 JWT access/refresh token 机制。

### 2.2 领域 / 路线 / Task 的层级

建议概念层次：

```text
领域 / 学习路线
  ↓
Learning Task（可完成目标）
  ↓
Learning Session（一次实际学习过程）
  ↓
Conversation / 活动 / 练习 / 群聊 / 资料阅读
```

例如：

```text
Java 后端
  ↓
理解 Spring 事务传播机制
  ↓
今天的学习 Session
  ↓
单聊 + 示例 + 费曼复述 + 练习
```

## 3. Task 创建与归属：用户只管学，Agent 负责维护

核心原则：

> **用户只管学，系统负责记住“正在学什么、学到哪里、接下来什么”。**

### 3.1 默认自动判断

用户不需要在开始学习前手工创建、命名、分类 Task。

Agent 应根据：

- 当前输入；
- 已有 Learning Task；
- 最近学习上下文；
- 长期学习状态；
- 任务目标差异；

自动判断当前内容应当：

1. 继续已有 Task；
2. 切换到已有 Task；
3. 创建新的 Task；
4. 仅作为当前 Task 中的小缺口就地处理。

### 3.2 低成本纠正

自动判断不能成为黑盒强制行为。

必须允许用户低成本纠正，例如：

- “这个属于另一个任务”；
- “这个我已经会了”；
- “不要新建任务”；
- “先学 Redis”；
- “回到刚才的事务传播”。

核心原则：

> **自动判断 + 用户低成本纠正。**

---

## 4. 学习状态：接触过 ≠ 理解了 ≠ 能独立使用

Study Agent 不得把“聊过”“读过”“Agent 已解释”直接当作掌握。

至少应区分以下学习状态：

1. **接触过**：用户已经看过或讨论过；
2. **理解了**：用户表现出对原理、关系或原因的理解；
3. **能独立使用**：用户能够复述、迁移、应用或解决变化后的问题。

建议 Task 状态：

```text
○ 未开始
◐ 学习中
◉ 待验证
✓ 已掌握
↻ 需要复习
```

避免使用仅代表项目管理语义的“已完成”作为唯一终态。

### 4.1 掌握应基于证据

推荐使用证据化状态，而不是机械百分比。

有效证据可包括：

- 能用自己的话解释；
- 能解释为什么；
- 能区分相似概念；
- 能发现或纠正错误；
- 能完成变化后的例子；
- 能用于实际代码 / 项目问题；
- 间隔后仍能回忆。

不应仅因为：

- 消息数量增加；
- Agent 讲解完成；
- 用户打开过资料；
- 群聊讨论过该主题；

就判定掌握。

### 4.2 验证嵌入自然对话

硬原则：

> **验证默认嵌入自然对话，不做成每学一点就弹出的考试流程。**

例如：

- 费曼复述；
- 自己举例；
- 解释一段源码；
- 解决一个变化后的问题；
- 对错误答案进行自我修正；

都可以自然成为学习证据。

Agent 可以判断“达到验证时机”，但不能偷偷替用户宣告“已经掌握”。用户保留最终确认权。

## 5. 学习路线：可见但自动维护的动态路线

Study Agent 应维护一张**可解释、可纠正、动态变化**的学习路线。

它不是用户手工维护的 Todo List，也不是不可修改的课程真理。

### 5.1 首页只露出当前与下一步

首页核心信息应接近：

```text
继续当前目标

看懂 Spring 事务传播机制
下一步：理解 REQUIRED 与 REQUIRES_NEW

学习路线 · 4/9
已掌握 → 当前 → 接下来
```

完整路线按需展开。

### 5.2 完整路线示例

```text
Java 后端
   ↓
Spring IoC
   ↓
Spring AOP
   ↓
事务代理        ✓
   ↓
事务传播机制    ← 当前
   ↓
事务失效场景
   ↓
实际项目排错
```

### 5.3 自动维护，不要求用户规划

路线由 Agent 根据以下信息持续调整：

- 当前目标；
- 历史学习证据；
- 用户错误与薄弱点；
- 用户新的目标；
- 用户主动调整优先级；
- 前置知识依赖；
- 实际项目 / 面试 / 课程场景。

用户一句：

- “这个我已经会了”；
- “这块先跳过”；
- “我现在主要为了面试”；
- “先学 Redis”；

都可以触发路线重算。

核心原则：

> **路线图是 Agent 对当前学习状态的判断，不是不可修改的课程真相。**

## 6. 前置知识：软导航，而不是课程锁

Study Agent 有**主动提醒权**，没有**强制阻止权**。

当检测到明显前置知识缺口时：

- 说明为什么该缺口可能阻碍当前目标；
- 给出最小补强方案；
- 允许用户直接继续当前目标。

推荐交互：

```text
这个问题可以直接讲，但它依赖「动态代理」。
你之前对这一块还没有形成稳定掌握证据。

建议先用 5 分钟补一下。

[先补前置] [直接继续]
```

### 6.1 不制造 Task 爆炸

只有当缺口会**显著阻碍当前目标**时，才值得创建或建议新的前置 Learning Task。

小缺口应直接在当前 Session 中补掉，不应自动拆成大量细碎任务。

核心原则：

> **Agent 可以改变推荐路径，但不能剥夺用户选择路径的权力。**

---

## 7. 角色与教学策略：严格分离

核心原则：

> **角色负责人格、关系和表达；学习策略负责教学行为。**

> **不要把知识能力硬绑定到角色。**

### 7.1 单聊中的角色

角色主要决定：

- 语言习惯；
- 互动方式；
- 情感距离；
- 主动程度；
- 人格连续性；
- 长期关系感。

角色不垄断某种知识能力。

用户喜欢哪个角色，不应该成为获得高质量教学的代价。

### 7.2 教学策略

教学策略由 Agent 根据：

- Learning Task；
- 当前学习状态；
- 用户错误；
- 证据缺口；
- 当前上下文；

动态选择。

例如：

- 苏格拉底追问；
- 费曼复述；
- 源码拆解；
- 示例驱动；
- 迁移练习；
- 概念图；
- 项目推进；
- 论文分析。

现有“学习模式”应在后续产品重构中重新分类，避免把“教学策略 / 任务类型 / 输出工具”混在同一个下拉框里。

### 7.3 Lab 中保留强制覆盖

普通界面不应要求用户持续操作：

```text
角色
学习模式
模型
性能档
Context 深度
```

高级用户仍可在 Lab 中强制覆盖，例如：

```text
角色 = 纳西妲
策略 = Socratic
模型 = Pro
Context = Deep
```

## 8. 群聊：持续存在的学习伙伴空间

群聊不是 Learning Task 的替代品，也不能降级成简单“多 Agent 回答按钮”。

推荐定位：

> **群聊是持续存在的学习伙伴空间 + 多视角学习机制。**

它可以脱离当前 Learning Task 独立存在，保留：

- 角色持续关系；
- 群聊开场；
- 未读感；
- 自由聊天；
- 学习伙伴氛围；
- 长期人格连续性。

但真正的学习状态 owner 仍然是 Learning Task。

### 8.1 群聊中的动态认知职责

群聊必须避免四个角色轮流重复同一种回答。

角色拥有长期 Persona，但在每轮讨论中可以被动态赋予不同**认知职责**。

例如 Spring 事务问题：

```text
纳西妲 → 建立原理模型
刻晴   → 追问工程后果
三月七 → 提出最容易产生的误解
流萤   → 给出真实故障场景
```

换到数学问题时职责可以重新分配：

```text
纳西妲 → 几何直觉
刻晴   → 严格推导
三月七 → 找“不懂的地方”
流萤   → 做迁移例题
```

核心原则：

> **角色是长期身份；认知职责是本轮动态分工。**

### 8.2 群聊学习成果归档

群聊中产生的有效学习结论可以：

- 归档到当前 Learning Task；
- 形成待验证知识点；
- 产生下一步建议；
- 产生资料或练习建议。

但是群聊本身不能直接把用户能力状态改成“已掌握”。

硬边界：

> **NPC 对话可以产生建议，不能产生用户学习证据。**

角色之间自己讨论不能证明用户已经理解或掌握任何内容。

## 9. Agent 主动性：应用内主动，应用外克制

总原则：

> **主动准备 > 主动打扰。**

> **Agent 不仅要知道什么时候介入，还要知道什么时候闭嘴。**

### 9.1 正在学习时：高主动

进入 Learning Session 等价于用户授权 Agent 在本次学习中主动教学。

Agent 可以主动：

- 追问；
- 发现误区；
- 切换教学策略；
- 插入最小前置补强；
- 提出自然验证；
- 引导迁移；
- 判断是否应该推进下一步。

### 9.2 用户打开 App 后：高主动但不打扰

首页不应回到通用“有什么可以帮你”。

应主动呈现：

- 上次学到哪里；
- 当前 Learning Task；
- 下一步建议；
- 适合复习的知识；
- 群聊中与当前学习有关的动态；
- 必要的路线变化。

### 9.3 用户离开 App 后：主动准备，默认不打扰

系统可以准备：

- 下一步建议；
- 薄弱点；
- 迁移问题；
- 待复习知识；
- 群聊值得讨论的问题；

但默认不发送应用外消息。

### 9.4 应用外主动联系：允许，但默认关闭

应用外通知必须显式 opt-in。

允许的高价值触发应限制在：

- 复习到期；
- 用户自己设定的重要学习计划；
- 考试 / 截止节点；
- 用户明确订阅的学习伙伴提醒。

默认禁止把以下内容作为主动通知理由：

- 为 DAU 制造消息；
- 随机寒暄；
- “你几天没学习了”；
- 无意义制造未读；
- 角色为了存在感随机打扰。

## 10. 群聊离线行为：默认不持续后台生成

群聊需要有“持续存在”的感觉，但不能通过无限后台生成对话来实现。

当前默认方向：

> **用户离开时不持续生成大量群聊；用户回来后，根据期间真实发生的学习事件、任务变化和复习状态，生成或整理“伙伴们想和你说的内容”。**

这样可以保留：

- 群聊是活的；
- 角色具有连续关系；
- 有合理的未读和回归感；

同时避免：

- Token 成本无限增长；
- 产生几十条垃圾未读；
- AI 自己聊天污染长期记忆；
- 角色为了制造活跃度无意义发言；
- NPC 对话被误记为用户学习证据。

未来如增加真正后台群聊，应单独进行成本、记忆污染、通知频率和学习价值验证，不能默认开启。

## 11. 当前建议的信息架构

一级学习产品建议趋向：

```text
首页 / 学习
│
├─ 继续当前目标
│   ├─ 当前 Learning Task
│   ├─ 上次停留位置
│   ├─ 下一步
│   └─ 学习路线摘要
│
├─ 学习伙伴群
│   ├─ 持续群聊空间
│   └─ 与学习任务互相归档 / 引用
│
├─ 学习路线
│   └─ 完整动态路线图
│
└─ Lab
    ├─ 模型 / Provider
    ├─ 路由
    ├─ RAG 调试
    ├─ Tool / Workflow
    ├─ 性能 / 成本
    └─ 高级强制设置
```

Conversation 是上述流程中的交互记录，而不是一级信息架构中心。

## 12. 当前产品差异化方向

Study Agent 不应单独与以下类别正面竞争：

- 通用 AI 聊天；
- 单纯 Socratic Tutor；
- 固定 AI 课程；
- 单纯角色陪伴；
- 纯 Multi-Agent 群聊。

当前更有价值的组合定位是：

> **一个记得用户长期学习状态、能够自动维护动态路线、拥有持续角色关系与多视角群聊、但尊重用户自主权的学习伙伴系统。**

关键组合能力：

```text
Learning Task
+ 动态学习路线
+ 可验证掌握证据
+ 自然教学策略
+ 长期角色关系
+ 多视角群聊
+ 长期记忆
+ RAG / 源码 / 资料能力
+ 克制而可解释的主动性
```

---

## 13. 后续实现必须遵守的硬边界

1. 不把首页重新做成 Agent 控制台。
2. 不要求用户手工维护 Learning Task 才能开始学习。
3. 不把聊天条数、阅读次数直接当掌握证据。
4. 不把所有小知识缺口拆成独立 Task。
5. 不通过强制前置锁阻止用户学习自己想学的内容。
6. 不把某一知识领域永久绑定到某个角色。
7. 不让群聊退化成多个角色重复同一答案。
8. 不允许 NPC 自己的对话改变用户掌握状态。
9. 不把后台工程设置继续堆回主学习界面。
10. 不默认开启应用外主动打扰。
11. 不通过无限后台群聊制造陪伴感和未读量。
12. 不用不可解释的“掌握度 83%”替代可追溯学习证据。

---

## 14. 尚未锁定的问题

以下内容仍需继续 GrillMe，不应在实现中提前拍板：

1. Learning Task 的最小数据模型与生命周期细节；
2. Learning Route 是 DAG、阶段列表还是混合结构；
3. 学习证据如何评分、衰减和冲突处理；
4. “需要复习”的触发机制与间隔学习策略；
5. 教学策略自动切换的规则与用户覆盖方式；
6. 群聊一次讨论应由谁决定参与角色数量与发言轮次；
7. 群聊“未读”到底代表真实后台事件还是回归时合成事件；
8. 首页最终布局与移动端信息密度；
9. 现有旧版 Streamlit 功能哪些保留、降级、迁移至 Lab 或删除；
10. 当前 PRD 中学习模式、性能模式、互动氛围、模型选择的重新归类方案。

---

## 15. 当前一句话原则

如果后续某个产品设计出现冲突，优先用以下一句话判断：

> **用户只管学；Study Agent 负责记住目标、理解当前状态、准备下一步，并在不夺走用户选择权的前提下主动帮助。**
