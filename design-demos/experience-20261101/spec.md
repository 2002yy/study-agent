# Study Agent 体验重构：共同输入

基线：main `abf40b494272c547f1fe29ca15edd13c4c470e7b`，2026-11-01。
交付：六候选缩略图 + 三个独立、可点击、离线 HTML 原型；1440×900 桌面与 375×812 移动端。
当前阶段是方向选择，不改生产 UI，不连接产品后端，不发起模型或检索调用。

## 内容与任务

目标是安静而流畅的聊天和研究界面：问题、实质回答、可追溯来源、随时补充和附件。降低模式开关、研究状态与诊断信息对阅读的打扰。与用户保持连续对话，不把研究变成另一个表单。

三版共享问题：**为什么 WAL 模式能改善读写并发？**
示例答案：写入先追加到日志，读者继续读取自己的快照，因此读和写通常可以并行。但同一时刻仍只有一个写入者，长读事务也可能阻碍 checkpoint 推进。用“读者 / 数据库快照 / 写入者 / WAL 日志”的小示意图帮助理解。
来源：https://www.sqlite.org/wal.html，已在本轮核实。只做中文转述，不声称发生真实研究。
每版明确标注“交互设计演示 · 非真实模型回答”；不能出现伪造耗时、成功率、来源已验证状态。
继续追问例：“那长事务会带来什么影响？”、“给我一个具体例子”。

## 共同交互

- 来源按钮展开或切换来源阅读区域；外链可访问官方文档。
- 输入支持非空发送、中文 IME 不误发；演示回复明确是本地预置内容。
- 新对话清空演示消息；给用户回到示例的入口。
- 附件只展示本地选择文件名，明确不会上传。
- 375px 无水平溢出，触摸目标 ≥44px，移动正文 16px，reduced-motion 支持。
- 按钮均有实际操作；设置可为真实文本字号/主题开关，不能做空按钮。
- 零外部字体依赖，字体用 Segoe UI / Microsoft YaHei / 系统字体。
