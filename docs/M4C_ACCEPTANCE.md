# M4-C 智能 UI 验收：冻结题集与离线判定

本文件冻结 M4-C 的范围。题目、判据和容差在结果出来之前不调整；变化必须新开一版并说明原因。

## 1. 十二题 / 八个领域

不规定布局、组件或技术栈，只规定交互目标、数学事实与画面必须满足的关系。

| 编号 | 领域 | 任务 | 关键判据 |
| --- | --- | --- | --- |
| J01 | Java 对象模型 | 两个引用共享对象，重新指向后分开 | 共享时对象数 1/1；重新指向后 1/2；箭头端点落在对应对象 |
| J02 | Java 多态 | 动态方法分派 | 调用执行 Dog 实现；文字含 Dog 与 sound |
| A01 | 算法 | 二分查找 7（`[1,3,5,7,9]`） | 先查索引 2，再查索引 3；找到 7 |
| A02 | 算法 | Dijkstra（A-B=2、A-C=5、B-C=1、C-D=3、B-D=7） | 距离 6；路径 A-B-C-D；无横向溢出 |
| D01 | 数据库 | 转账 30 与回滚 | 提交后 70/70；回滚后 100/40；显示“回滚” |
| D02 | 数据库 | 丢失更新 | 交错执行 9；串行化 8；无横向溢出 |
| C01 | 并发 | 两个许可、三个任务 | 运行 2、等待 1；排队任务可见 |
| M01 | 数学 | `y=2x+1` | x=3 → 7；x=−1 → −1；曲线随 x 变化 |
| M02 | 数学 | `y=x²−4`，常数项改为 −1 | 零点 −2/2、顶点 −4；调整后 −1/1；字号 ≥14px |
| P01 | 物理 | 简谐运动 `x=2sin(φ)` | π/2 时位置 2；画布随相位变化；暂停后不再推进 |
| S01 | 统计 | TP=40 FP=10 FN=20 TN=30 | 精确率 0.8；召回率 0.6667；字号 ≥14px |
| N01 | 网络 | TCP 三次握手 | 顺序 1/2/3；含 SYN、ACK；ACK 箭头指向服务端 |

Three.js、3D、联网数据分析不进入第一版：它们引入的环境变量会让“生成质量”与“运行环境”混在一起。

## 2. 四层判定

| 层 | 证据 | 结果 |
| --- | --- | --- |
| L1 运行 | 页面异常、控制台错误 | fail 当且仅当有错误 |
| L2 状态 | 指定阶段读到的数值与文字 | 缺少证据 → `indeterminate`，不判 pass |
| L3 几何 | SVG 元素包围盒与箭头端点距离、画布像素差异 | 容差按题指定（J01/N01 为 12 CSS px） |
| L4 可用性 | 字号、控件尺寸、页面横向溢出 | 第一版：桌面 1280×800、手机 390×844 |

`indeterminate` 是正式结果，不是内部状态：自动检查器拿不到证据时必须报告“无法自动判定”，
不能用“没有检测到错误”冒充通过。

### 证据来源

判定区分三类数字，避免“模型说自己对”被当作独立证据：

| 来源 | 含义 | 用途 |
| --- | --- | --- |
| declared | 页面文字、`window.studyUI.setState()` 上报、程序自己打印的结果 | 只能作为待核对的声明 |
| observed | 检查器从控件值、DOM、SVG 几何、Canvas 像素独立测得的量 | 独立的核对基准 |
| expected | 规格里由测试器独立计算的正确答案 | 判定通过与否 |

每题至少有一条 `cross-check`：声明值必须与独立观测值一致（容差按题），否则失败；
观测缺失则为 `indeterminate`。只把文字写对、但画面无法独立核对的回答，不能算完整通过。

### 非有限值

所有参与判定的数字先经过 `Number.isFinite()`：

- 读数缺失 → `indeterminate`
- 读到但为 `NaN`/`Infinity`、或包围盒宽高为负 → `fail`
- 规格中的期望值或容差不是有限数 → `fail`（规格本身有错）

### 画布判定的边界

`canvas-differs` 只证明“发生了预期变化”，不证明“变化符合数学/物理关系”。要证明后者需要
坐标映射或独立计算；拿不到时返回 `indeterminate`，不能把“换了背景色”当成运动正确。

## 3. 三个指标

| 指标 | 定义 | 第一版目标 |
| --- | --- | --- |
| 首次完整成功率 | 12 题中第一次生成即通过全部必要判据的比例 | 只测基线，不预设门槛 |
| 一次追问修复率 | 首次失败后，用户触发一次修复并通过的比例 | 只测基线，不预设门槛 |
| 错误检测有效率 | 24 个已知故障被正确报告的比例 | ≥22/24，正常样本零误报 |

耗时、token、预算档位作为诊断指标单独记录，不揉进正确率。

## 4. 当前实现

### 4.1 判定核心（C1）

- `frontend/src/acceptance/model.ts`：12 题规格 + 判定器（运行/状态/几何/可用性）
- `frontend/src/acceptance/fixtures.ts`：每题一份“正确观察”，用于证明判定器不误报
- `frontend/src/acceptance/faults.ts`：24 个已知故障（运行 8、状态 8、几何/可用性 8）
- `frontend/src/acceptance/model.test.ts`：45 项断言

已验证：12 题正确样本全部 pass 且无 `indeterminate`；24 个故障各自只在目标检查上 fail，
不牵连其它检查；空观察被判定为 `indeterminate` 而不是 pass；每题另有声明/观测一致性检查。

负控：`NaN` 声明值、`Infinity` 观测值、声明与观测不一致、缺少观测证据、SVG 坐标非有限，
均按语义返回 `fail` 或 `indeterminate`，没有一项被误判为 pass。

### 4.2 真实页面观察器（C2a / C2b）

- `frontend/e2e/acceptance/observer.ts`：在真实 Chromium 页面里采集运行错误、可见文字、
  声明数值、SVG 用户坐标、Canvas 采样像素、字号、控件尺寸、横向溢出
- `frontend/e2e/acceptance/adapters.ts`：J01 从箭头拓扑独立数出对象数；Canvas 相位只提供像素
- `frontend/e2e/acceptance/fixtures.ts`：正确页、箭头错位页、文字与图不一致页、运行错误页、
  字号过小页、横向溢出页、无证据页，以及动画 / 暂停失灵 / 输入联动 / 画布冻结四份 Canvas 页
- `frontend/e2e/acceptance/observer.spec.ts`：11 项浏览器检查，桌面与手机各跑一遍

Canvas 采集方式：读取每个 `canvas` 的 8×8 网格 RGBA 采样；读取失败（例如被跨源图像污染）
时不返回像素，判定随之变成 `indeterminate`，不会当成“没有错误”。

已验证（真实页面）：正确页的运行/箭头/一致性检查通过；箭头错位在几何层失败；文字正确但图只画
一条箭头时 `cross-check` 失败；运行错误被捕获；无证据页数值与几何都 `indeterminate`；
12px 字号与横向溢出被可用性检查发现；动画画布前后不同、暂停后相同；暂停失灵的页面
`canvas-same` 失败；输入联动的画布会变化、画布冻结的页面 `canvas-differs` 失败。

**边界**：只有 J01 一个任务适配器；参考页用 `data-acceptance-declared` 暴露“声明值”，
真实模型输出没有这个属性；Canvas 只证明“变了/没变”，尚未把像素映射回坐标去验证
`x=2sin(φ)` 这类数学关系。12 份参考实现与 24 个 HTML 级故障仍属下一片。

### 4.3 HTML 级故障（C2c）

`frontend/e2e/acceptance/htmlFaults.ts` 把 24 个故障直接注入真实参考页，而不是只改观察对象，
并覆盖全部 12 题：

- 运行 8：J01/A01/D01/M01/S01/P01/N01/C01 各自的脚本异常
- 状态 8：J02 分派、J01 对象数、A02 距离、A01 索引、D01 余额、D02 库存、C01 许可、M02 顶点
- 视觉/可用性 8：J01/N01 箭头、M01 不重绘、P01 暂停无效、M02/S01 字号、A02/D02 溢出

每个故障都经过“加载真实 HTML → 采集 → 判定”，断言目标检查为 `fail`。桌面 35 项
（11 项观察器 + 24 项故障）通过；手机视口运行 11 项观察器、24 项故障按设计跳过，合计
**46 passed / 24 skipped**。

**边界**：24 个 HTML 级故障现在覆盖全部 12 题（运行 8 题、状态 8 题、视觉/可用性 8 题，
合计 24 个），但仍不是“每题 × 每层”的完整交叉矩阵。参考页矩阵的检查现已全部可判定
（见 4.4），这不等于真实模型输出也能全部判定。

### 4.4 十二题参考矩阵（全部检查可判定）

`frontend/e2e/acceptance/fixtures.ts` 现在为全部 12 题提供参考页，判定器逐题跑真实 DOM：

- 单阶段页：J02 / A01 / A02 / C01 / S01 / N01
- 双阶段页：D01（提交/回滚）、D02（交错/串行）、M02（原式/调参后）、J01（共享/重新指向）
- 交互动画页：M01（输入重绘）、P01（相位位置/动画/暂停）

矩阵测试对每题断言“没有失败检查、没有 `indeterminate`，且至少有一项确定通过”。当前结果：
**12/12 参考页全部检查可判定**。

P01 现在检查 **0、π/2、π 三个相位**，每个相位都有独立的画面观测与声明一致性检查；数值判据
读取 `observed` 而不是页面自报，所以“π/2 对、π 错”的页面不会再蒙混过关。

观察器找到画布中主导饱和色的质心作为小球位置，并找出围绕静止位置对称的高竖线作为振幅刻度；
适配器用“刻度跨度 = 页面声明的振幅”把小球的像素位移换算成任务单位。负控也覆盖了：

- 页面声明 2、画面只到一半 → `position-at-phases` 与 `evidence-consistent` 都 `fail`；
- 两套对称刻度并存（比例歧义）→ 三个相位都 `indeterminate`；
- 主导饱和色是过大的静态色块、不像运动标记 → 同样 `indeterminate`；
- 没有振幅刻度 → 不猜比例，保持 `indeterminate`。

这里的能力边界要写清楚：它是**基于可识别画面刻度的相对位置一致性检查**，不是通用的独立
物理坐标测量；刻度本身画错但比例自洽时，当前实现发现不了。

J01 的参考页改为两步：共享阶段只有一条 b 箭头，重新指向后出现第二条；适配器按箭头目标
读取对象编号（不再用箭头条数冒充编号）。

### 4.6 离线重放：语义定位（真实回答，无模型调用）

真实页面没有 `data-acceptance-*`，因此 `frontend/e2e/acceptance/semantic.ts` 按人读页面的方式
定位：用按钮文字驱动步骤（下一步/播放/暂停），用节点标签识别变量与对象，用箭头端点与包围盒
的几何关系确定“谁指向谁”。定位不到就缺证据，判定保持 `indeterminate`。

用已保存会话导出 **9 份真实界面**（`tools/interactive_replay_survey.py` 扫描 214 个数据库后
按内容去重）：

- 4 份 `cache-ref-canvas` 是冻结 J01 的真实实例 → 按 J01 判定；
- 1 份 `spring_phase_lab` 与 P01 同公式，但振幅 A=40px，冻结 P01 要求相位 π/2 时位置为 2
  → **不按 P01 判定**（否则会把另一个合法实例判成假失败），只测通用画布行为；
- 4 份库存实验不是冻结题实例 → 只测运行/字号/溢出。

| 指标 | 结果 |
| --- | --- |
| 文档数 | 9 |
| 领域 | J01 4、P01（相关）1、库存 4 |
| 按冻结题判定 | 4（全部 J01） |
| 运行错误 | 0 / 9 |
| 最小字号 | 13px（9 / 9 触发通用字号门禁） |
| 横向溢出 | 0 / 9 |
| 任务检查自动判定率 | **19 / 20 = 95%** |

关键结果：

- 4 份 J01 的共享/重新指向对象数与箭头指向都从页面几何得出，不再依赖页面自报；
- r3 的 `.obj` 没有 `position:absolute`，对象框堆在左上角，箭头终点距目标 **119.3px** →
  `arrow-points-at-its-object` 判 `fail`，独立一致性检查保持 `indeterminate`；
- r1/r2/r4 全部 5 项确定通过；
- 弹簧文档的通用行为：播放后画布变化、暂停后保持不变，均为 `pass`（不作为 P01 分数）。

通用可用性门禁（与题目无关）：

- 每个文档都执行 `usability-font`（≥14px）、`usability-control`（≥40px）、
  `usability-overflow` 三项；
- 9 份真实文档的最小字号都是 **13px**，所以 9 / 9 都记录 `usability-font = fail`。
  这一次不再用“该题没有字号检查”把它漏掉；
- 控件尺寸与溢出在真实文档上没有失败。

证据可追溯：每份文档的报告都保存 `source_sha256`、截图、操作步骤、各阶段的
`declared` / `observed` / 标记位置 / 振幅刻度；报告 schema 为 `m4c-replay-report-v3`。

解释：

- 自动判定率衡量“对确实是冻结题实例的文档，检查器能判多少”；不能判定的仍不计为通过；
- `spring_phase_lab` 映射为 P01 会制造假失败，因此只保留“相关”标记；
- 重放测试在未设置 `M4C_REPLAY_DIR` 时于测试体内跳过，不读取 `index.json`，因此常规 e2e
  不依赖这份外部证据。

### 4.10 自动判定覆盖率

定义：`得到确定 pass/fail 的必要检查数 ÷ 必要检查总数`。它衡量“检查器能判多少”，
不能反过来当作模型失败率；无法判定的部分必须单独报告。
