# M4-C 智能 UI 验收：冻结题集与离线判定

本文件冻结 M4-C 的范围。题目、判据和容差在结果出来之前不调整；变化必须新开一版并说明原因。

## 1. 十二题 / 八个领域

不规定布局、组件或技术栈，只规定交互目标、数学事实与画面必须满足的关系。

| 编号 | 领域 | 任务 | 关键判据 |
| --- | --- | --- | --- |
| J01 | Java 对象模型 | 两个引用共享对象，重新指向后分开 | 共享时对象数 1/1；重新指向后 1/2；箭头端点落在对应对象 |
| J02 | Java 多态 | 动态方法分派 | 调用执行 Dog 实现；文字含 Dog 与 sound |
| A01 | 算法 | 二分查找 7（`[1,3,5,7,9]`） | 先查索引 2，再查索引 3；找到 7 |
| A02 | 算法 | Dijkstra（A-B=2、A-C=5、B-C=1、C-D=3、B-D=7） | 距离 6；路径 A-B-C-D；无横向溢出 |
| D01 | 数据库 | 转账 30 与回滚 | 提交后 70/70；回滚后 100/40；显示“回滚” |
| D02 | 数据库 | 丢失更新 | 交错执行 9；串行化 8；无横向溢出 |
| C01 | 并发 | 两个许可、三个任务 | 运行 2、等待 1；排队任务可见 |
| M01 | 数学 | `y=2x+1` | x=3 → 7；x=−1 → −1；曲线随 x 变化 |
| M02 | 数学 | `y=x²−4`，常数项改为 −1 | 零点 −2/2、顶点 −4；调整后 −1/1；字号 ≥14px |
| P01 | 物理 | 简谐运动 `x=2sin(φ)` | π/2 时位置 2；画布随相位变化；暂停后不再推进 |
| S01 | 统计 | TP=40 FP=10 FN=20 TN=30 | 精确率 0.8；召回率 0.6667；字号 ≥14px |
| N01 | 网络 | TCP 三次握手 | 顺序 1/2/3；含 SYN、ACK；ACK 箭头指向服务端 |

Three.js、3D、联网数据分析不进入第一版：它们引入的环境变量会让“生成质量”与“运行环境”混在一起。

## 2. 四层判定

| 层 | 证据 | 结果 |
| --- | --- | --- |
| L1 运行 | 页面异常、控制台错误 | fail 当且仅当有错误 |
| L2 状态 | 指定阶段读到的数值与文字 | 缺少证据 → `indeterminate`，不判 pass |
| L3 几何 | SVG 元素包围盒与箭头端点距离、画布像素差异 | 容差按题指定（J01/N01 为 12 CSS px） |
| L4 可用性 | 字号、控件尺寸、页面横向溢出 | 第一版：桌面 1280×800、手机 390×844 |

`indeterminate` 是正式结果，不是内部状态：自动检查器拿不到证据时必须报告“无法自动判定”，
不能用“没有检测到错误”冒充通过。

### 证据来源

判定区分三类数字，避免“模型说自己对”被当作独立证据：

| 来源 | 含义 | 用途 |
| --- | --- | --- |
| declared | 页面文字、`window.studyUI.setState()` 上报、程序自己打印的结果 | 只能作为待核对的声明 |
| observed | 检查器从控件值、DOM、SVG 几何、Canvas 像素独立测得的量 | 独立的核对基准 |
| expected | 规格里由测试器独立计算的正确答案 | 判定通过与否 |

每题至少有一条 `cross-check`：声明值必须与独立观测值一致（容差按题），否则失败；
观测缺失则为 `indeterminate`。只把文字写对、但画面无法独立核对的回答，不能算完整通过。

### 非有限值

所有参与判定的数字先经过 `Number.isFinite()`：

- 读数缺失 → `indeterminate`
- 读到但为 `NaN`/`Infinity`、或包围盒宽高为负 → `fail`
- 规格中的期望值或容差不是有限数 → `fail`（规格本身有错）

### 画布判定的边界

`canvas-differs` 只证明“发生了预期变化”，不证明“变化符合数学/物理关系”。要证明后者需要
坐标映射或独立计算；拿不到时返回 `indeterminate`，不能把“换了背景色”当成运动正确。

## 3. 三个指标

| 指标 | 定义 | 第一版目标 |
| --- | --- | --- |
| 首次完整成功率 | 12 题中第一次生成即通过全部必要判据的比例 | 只测基线，不预设门槛 |
| 一次追问修复率 | 首次失败后，用户触发一次修复并通过的比例 | 只测基线，不预设门槛 |
| 错误检测有效率 | 24 个已知故障被正确报告的比例 | ≥22/24，正常样本零误报 |

耗时、token、预算档位作为诊断指标单独记录，不揉进正确率。

## 4. 当前实现

### 4.1 判定核心（C1）

- `frontend/src/acceptance/model.ts`：12 题规格 + 判定器（运行/状态/几何/可用性）
- `frontend/src/acceptance/fixtures.ts`：每题一份“正确观察”，用于证明判定器不误报
- `frontend/src/acceptance/faults.ts`：24 个已知故障（运行 8、状态 8、几何/可用性 8）
- `frontend/src/acceptance/model.test.ts`：45 项断言

已验证：12 题正确样本全部 pass 且无 `indeterminate`；24 个故障各自只在目标检查上 fail，
不牵连其它检查；空观察被判定为 `indeterminate` 而不是 pass；每题另有声明/观测一致性检查。

负控：`NaN` 声明值、`Infinity` 观测值、声明与观测不一致、缺少观测证据、SVG 坐标非有限，
均按语义返回 `fail` 或 `indeterminate`，没有一项被误判为 pass。

### 4.2 真实页面观察器（C2a）

- `frontend/e2e/acceptance/observer.ts`：在真实 Chromium 页面里采集运行错误、可见文字、
  声明数值、SVG 用户坐标、字号、控件尺寸、横向溢出
- `frontend/e2e/acceptance/adapters.ts`：J01 适配器，从箭头拓扑独立数出对象数
- `frontend/e2e/acceptance/fixtures.ts`：正确页、箭头错位页、文字与图不一致页、运行错误页、
  字号过小页、横向溢出页、无证据页
- `frontend/e2e/acceptance/observer.spec.ts`：7 项浏览器检查，桌面与手机各跑一遍

已验证（真实页面，非手写观察）：正确页的运行/箭头/一致性检查通过；箭头错位在几何层失败；
文字正确但图只画了一条箭头时，声明检查通过而 `cross-check` 失败；运行错误被捕获；没有证据的
页面数值与几何都返回 `indeterminate`；12px 字号与横向溢出分别被可用性检查发现。

**边界**：目前只有 J01 一个任务适配器；参考页用 `data-acceptance-declared` 暴露“页面声明值”，
真实模型输出没有这个属性，需要后续用语义标签与几何启发式定位，定位不到就返回
`indeterminate`。Canvas 采集、12 份参考实现与 24 个 HTML 级故障仍属下一片。

### 4.3 自动判定覆盖率

定义：`得到确定 pass/fail 的必要检查数 ÷ 必要检查总数`。它衡量“检查器能判多少”，
不能反过来当作模型失败率；无法判定的部分必须单独报告。
