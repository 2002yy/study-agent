# Quality-0：真实任务质量基线（离线框架）

> 目的：把「用户是否真的得到更好答案」变成可重复测量的对象，而不是用测试数量代替。
> 本切片只建立**题集、评分表、评分汇总与判定规则**；不发起任何模型调用，也不改变产品行为。

## 为什么先做这一步

已有工程能力（研究运行时、状态、工具、费用控制、搜索、CI）都能通过静态测试，但缺少一个问题：
**改动之后，用户拿到的答案是否更好？** Quality-0 就是这个问题的最小闭环。

## 任务集

`tests/fixtures/quality_0/tasks_v1.json`，冻结于 2026-10-28，共 **20 个任务**，覆盖七个产品方向：

| 类型 | 数量 | 考察重点 |
| --- | ---: | --- |
| `chat` 自然聊天 | 3 | 上下文、改目标、被纠正后的更新 |
| `game` 游戏攻略 | 4 | 版本时效、配装理由、自动战斗、错误前提 |
| `coding` 编程技术 | 3 | 分层排查、模块边界判断、可执行解释 |
| `research` 综合研究 | 3 | 多来源比较、条件化选型、可核验计算 |
| `science` 科学问题 | 3 | 机制解释、实验可信度、概念区分 |
| `file` 文件任务 | 2 | 文档结论提取、数据统计与异常 |
| `interactive` 持续交互 | 2 | 追加约束、暂停后收敛 |

每题固定：`id`、`type`、`prompt`、`expected_behavior`、`checks`、`must_not`；多轮题另有 `follow_up`。
**冻结的是题目与评分标准，不是实时答案**（游戏题按运行时版本判定）。

## 对照臂

| 臂 | 用途 |
| --- | --- |
| `current` | Study Agent 当前版本 |
| `candidate` | 候选版本 |
| `model_direct` | 同一模型的直接对话（无检索/研究）——用于区分「模型问题」与「系统问题」 |
| `chatgpt` | 参考产品表现，**不是真值** |

## 评分维度（0–4，加权）

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| `task_completion` | 5 | 是否完成任务且可直接使用 |
| `factual_accuracy` | 5 | 关键事实是否正确 |
| `evidence_coverage` | 4 | 关键主张是否有可核验来源 |
| `usefulness` | 4 | 是否可执行、有重点 |
| `follow_up_correctness` | 3 | 仅多轮题：是否正确继承并只改必要部分 |
| `freshness` | 3 | 仅时效题：是否使用当前版本信息 |

`score_0_100` 按权重归一化；另记 `first_useful_seconds`、`total_seconds`、`cost_cny`。

## 使用流程（当前全部离线）

```powershell
# 1. 校验题集并查看清单
python tools/run_quality_0.py

# 2. 生成评分表骨架（每题 × 每臂 × 每维度）
python tools/run_quality_0.py --write-sheet

# 3. 人工/独立评审填表后汇总（未填完会被拒绝）
python tools/run_quality_0.py --summarize docs/research_quality/QUALITY_0_SCORING_SHEET.json
```

评分表完整性是硬约束：缺行或存在 `null` 分数时 `--summarize` 直接失败，避免「只评了喜欢的题」。

## 下一步（需要单独授权）

1. **真实运行**：四个臂各跑 20 题需要真实模型与搜索调用，属于**新的付费实验**，必须单独给预算；
   运行器将在那时新增，且默认离线、显式开关、账本留痕（沿用 QP-1C 的教训）。
2. **评分**：优先「人工 + 一个不参与路由/生成的模型」双评，报告分歧率；`chatgpt` 臂只作参考。
3. **诊断归属**：每个低分项必须标注责任层——模型理解 / 搜索排序 / 读取证据 / 综合回答 / 状态与工具 / 界面。
   只有定位到具体层，才允许开对应切片；否则先补证据。

## 与后续切片的关系

| 切片 | 依赖 Quality-0 的什么 |
| --- | --- |
| Routing-2 | 用同一题集比较排序前后的「有效来源进入前六」与最终得分 |
| Evidence-1 | 用 `evidence_coverage` 与「有效阅读率」定位证据缺口 |
| Answer-1 | 用 `task_completion` / `usefulness` 判断综合质量 |
| Conversation-1 | 用 `chat` / `interactive` 两类题判断上下文与约束处理 |

**Hit@6 只是诊断指标**，不是产品目标：它解释「为什么最终回答变好或变差」，不能替代任务完成率。

## 非范围

- 不改 `src/`、不改默认路由、不新增模型调用；
- 不把本框架当作已完成的动态验收：没有真实运行与独立评分之前，Quality-0 只有框架，没有结论。
