## Three-tier strategy remains frozen

| Tier | Purpose | Approximate planning budget |
| --- | --- | --- |
| Lookup | One explicit fact, version, date or parameter | 1–3 reads, 10–30 seconds |
| Standard | Small multi-source research, comparison and cross-checking | 5–8 reads, 60–90 seconds |
| Deep | Open-ended research with repeated gap-driven rounds | Adaptive, minutes |

These are the frozen strategy/calibration targets, not a claim that all existing
runtime limits or tier qualifications already meet them. This slice changes no
budgets, tier selection or Deep execution authority.

Discovery, candidate/read lifecycle, reader, identity resolution, evidence binding,
Gate and publication are reusable shared capabilities. Python is a Lookup
production identity/date example; Opus is an exact-version/mixed-content binding
example. Passing either, or all five source-quality observations, does not close
the whole research system.

Qualification order: shared foundation → Lookup → Standard → Deep. Lookup still
needs its budget/recovery/coverage qualification. Standard needs source diversity,
per-source binding, claim merging, conflict handling and supported comparisons on
both sides. Deep needs a separate claim/gap plan, Evidence Gain, convergence,
saturation/stop and interruption contract plus actual multi-round qualification.

## Locked implementation scope

An exact Opus query tries the official version-specific overview URL. This is a
candidate address, never evidence of a release existing. A successful bounded
HTTP read must retain the same final URL; redirects to overview/other versions
are rejected. Mixed-version comparison queries do not become single-version
Lookup requests.

The trusted reader preserves heading inline boundaries, including badges, so a
visible version and a following `Latest` label cannot become one token. The
adapter requires a single exact product h1, one matching reader-derived version
heading and a complete matching model ID within that heading section. Scripts,
navigation, later subsections and comparison tables cannot supply that ID.

Only the first positioning line under the matched heading is bound and published
verbatim, with original quote/heading/ID spans and decoded/canonical/transport
digests. Extended IDs, wrong versions, mixed identities, comparison introductions,
unread sources and fabricated source flags fail closed. The generic marker may
be replaced only by native reader-owned project/version fields and matching
normalized content digest. This proves exact source identity, not performance.

No pricing, capability, benchmark, release-date or comparison facts are extracted
from the rest of the page. Existing publication and interruption gates retain
authority; model prose is withheld. A positioning quote is not a verified
comparison, and the official label remains attached to the quoted statement.

The live observation exposed a Windows transport prerequisite: a NO_PROXY-only
environment hides registry proxies in CPython's default selection. The official
reader restores system proxies only when there is no explicit environment proxy;
existing bypass rules, including `*`, still apply. No environment/file mutation,
credential logging, hostname/redirect relaxation or region-page evidence is
permitted. This bounded transport correction also affects other official reads
and therefore requires their impact set and a new clean-head L3.

## Gates and limitations

Impact: Opus profile/identity/Python/official-source tests plus the source-quality
and semantic recovery integration sets. Heading-reader/publication changes force
one clean-head full backend L3, Ruff, mypy no-new-errors, diff/scope checks. A real
gateway/recovery → ChatService → SQLite observation must bind source/code/answer
digests and times; preserve the old failed Opus observation and negative controls.
Exact-head CI/review and protected merge precede exact-main delivery validation.

UTF-8, heading-only conservative boundaries and unsupported family/prerelease
planning remain explicit limitations. No paid search, login provider, UI change or
new semantic judge. Lookup qualification and overall research remain NOT CLOSED;
Standard and Deep qualification are separate subsequent stages.
