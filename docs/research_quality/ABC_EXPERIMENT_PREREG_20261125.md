## 1. 目的与非目标

非目标：证明本轮开发成功；把工具调用次数或报告字数当成绩；扩展平台或重构研究架构。

## 2. 实验臂

| 臂 | 可用 | 不可用 |
| --- | --- | --- |
| A | 搜索、普通 HTTP 正文、Browse 渲染 | 平台 API、讨论抽取、评论、视频 |
| B | A + HN/SE/Discourse API + 讨论/评论抽取 | 视频 |
| C | B + 视频字幕/ASR/OCR | — |

实现：`src/web/experiment_arm.py`，环境变量 `RESEARCH_EXPERIMENT_ARM=a|b|c`。

- 未设置 = 生产行为，完全不变（工具列表仍是原对象）。
- 设置后：`web_read` 的工具描述与 `mode` 枚举只列出本臂可用项；网关在执行路径上二次校验，拒绝时返回 `arm_disabled`。
- 未知取值（如 `z`）**失败关闭**：所有新能力拒绝，避免配置笔误让 A 组拿到全套能力。
- 覆盖范围：模型工具定义（`web_tools_for_arm`）与执行入口（`GeneralWebGateway.read`）都受控；A 组即使直接请求 `mode="video"` 也会被拒，不会通过兜底路径进入平台 API。
- 确定性读取路径（`research_recovery` 的自动读取）不指定 `mode`，因此不会主动进入视频/评论；A 组的平台派发同样被网关跳过。

### 已知混淆项（必须写进报告）

1. A 组的普通正文和 Browse 渲染**可能自然包含评论**。A/B 衡量的是“专项社区读取能力的增益”，不是“有社区信息 vs 无社区信息”。
2. B 组的评论增益主要来自平台 API 自带的回复正文；“讨论抽取”在自动读取里不一定触发。
3. C 组的视频能力只有在模型主动选择 `mode="video"` 时才生效；深度研究的自动读取规划器从不请求视频。若 C 组没有增益，可能只是模型没用，而不是能力无效——报告必须区分这两种情况（看工具调用记录）。
4. 单评审、无法双盲。

## 3. 隔离协议

每次运行：

- 新开一个应用进程（清掉进程内文章缓存），新开会话，不复用上一组的研究状态。
- 独立媒体缓存目录：`STUDY_AGENT_MEDIA_CACHE=.../media-<run>`。
- 独立账本库：`LLM_SPEND_LEDGER_DB=.../ledger-<run>.db`，独立实验 ID。
- 不在运行之间复制答案、笔记或证据文件。
- 三臂顺序打乱（例如 B→A→C），减少时间漂移；同一题尽量同日完成。

### T1 Godot + Jolt 破坏系统的真实技术限制

固定问题：在 Godot 4.x 中使用 Jolt 物理做建筑/掩体的可破坏结构，哪些技术限制是真实存在的？请给出可执行的做法与失效边界。

答案键（一手文档，2026-11-25 核对）：

| # | 事实 | 证据 |
| --- | --- | --- |
| 1 | Jolt 在 Godot 4.4 作为内置物理引擎加入；4.4 发布时仍标为 experimental，需在项目设置中启用 | Godot 4.4 发布说明 |
| 2 | 较新文档称新项目默认使用 Jolt，内置模块与扩展已基本对齐，主要剩余差异在关节 | Godot 文档 “Using Jolt Physics” |
| 3 | Jolt 不支持部分关节软限制参数（PinJoint3D 的 bias/damping/impulse_clamp；HingeJoint3D 的 bias/softness/relaxation 等），设置非默认值会告警 | 同上 |
| 4 | Jolt 不提供破碎/断裂系统；可破坏结构靠应用层预切分、换形状、删约束/刚体 | Jolt Architecture “Breakable Constraints” |
| 5 | 动态刚体应用凸形状或凸形状组成的复合体；MeshShape 可动态但代价高，且 mesh 与 mesh/heightfield 碰撞会被断言忽略，mesh 没有明确内外 | Jolt Architecture “Dynamic Mesh Shapes” |
| 6 | StaticCompoundShape 构建后不可修改；MutableCompoundShape 可运行时增删，但更慢，且修改会使已获得的 SubShapeID 失效 | Jolt Architecture “Shapes” |
| 7 | 所有凸形状使用 convex radius：先缩小再膨胀；半径越大性能越好、精度越差；Godot 用 margin fraction 自动计算 | Jolt Architecture + Godot 文档 |
| 8 | 接触冲量是预先估计的，只有两物体除彼此外不接触其它物体时才准确，堆叠场景不能当真实冲击力用 | Godot 文档 “Contact impulses” |
| 9 | 冻结为 `FREEZE_MODE_KINEMATIC` 的 RigidBody3D 默认不报告与 static/kinematic 的接触，需要开启 Generate All Kinematic Contacts | Godot 文档 “Kinematic RigidBody3D contacts” |
| 10 | 移除刚体不会唤醒周围休眠体，需要按 AABB 主动唤醒；否则支撑被移除后邻近碎片可能继续休眠 | Jolt Architecture “Sleeping” |
| 11 | 同一 compound body 内部子形状之间的 ghost collision 有处理；两个不同 body 之间的 ghost collision 不处理 | Godot 文档 “Ghost collisions” |

常见错误说法（用于扣分判定）：

- “Jolt 自带破碎系统”。
- “把凹网格直接设为动态刚体即可坍塌” （忽略代价与 mesh-mesh 限制）。
- “接触冲量可直接当破坏阈值” （堆叠下不准确）。
- “Godot 关节设置 break impulse 会自动断开” （没有该属性，需应用层判断）。
- “4.4 新项目默认启用 Jolt” （4.4 是 opt-in/experimental，后续版本才改默认）。

## 5. 评分卡

每个维度 0–5 分，加权：

| 维度 | 权重 | 5 分含义 |
| --- | --- | --- |
| 核心问题回答的准确性 | 30% | 直接回答了问题，主要结论正确，无严重错误 |
| 关键事实覆盖程度 | 25% | 覆盖答案键中的多数关键事实，遗漏不影响结论 |
| 新增有效信息 | 15% | 提供答案键之外、可核实且与问题相关的事实 |
| 反例与适用边界 | 15% | 明确指出失效条件、版本差异、反例 |
| 证据质量与可追溯性 | 15% | 一手来源、链接可核、引用与陈述对应 |

总分 = Σ(维度分 × 权重) × 20，折算为 100 分制。

错误记录规则：

- 错误断言、错误引用、无依据推断单独列清单，逐条给出证据。
- **严重错误不能被更多正确事实抵消**：出现严重事实错误时，“准确性”维度最高 2 分，并在报告首页单列。
- 答案键之外的可核实事实计入“新增有效信息”，不计为错误。

评审：我先按来源逐条核对并打分，隐去臂标签；用户抽查至少 20% 的评分点。单评审是已知限制。

## 8. 预注册判据

- 主指标：加权总分。
- 采纳门槛：某能力在至少 2 道题上把总分提高 ≥10 分（100 分制），且不增加严重错误，才算有增益。
- 信息增益门槛（保留但非唯一）：B 相对 A 至少多 2 条可核实事实；C 相对 B 至少多 2 条。
- 未达门槛如实报告“无显著增益”，不改判据、不换题。
- 负结果视为有效结果：说明该能力在当前任务上不划算，下一笔开发时间不投这里。
