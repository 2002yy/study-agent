# QP-1C：查询规划 A/B/C 真实模型实验（10 题）

> 目的：在 QP-1B 改进指令后，验证「模型生成的查询」相对「原始整句」是否真的带来更相关的检索结果，
> 以及新指令相对旧指令是否有增益。结论必须限定在本轮的题集、提供商和采样条件下。

## 预算与门禁

| 项 | 实际 |
| --- | --- |
| 授权上限 | 10 题、每题 ≤2 次、总计 ≤20 次、≤3 元 |
| 实际发送 | **20 次**（第一段 12 次 + 第二段 8 次） |
| 账本 | 预留 = 结算 = **1.073 元**（20 条 reservation / 20 条 settlement） |
| 定价写入守卫 | 输入 4 元 / 输出 16 元（每百万 token，**保守上界**，不是账单） |
| 门禁负控 | 缺定价时 `AdmissionConfigError: pricing_not_configured`；确认 fail-closed 后才开跑 |
| 模型 | `deepseek-flash`，`temperature=0`，沿用 `configured_completion`（`max_tokens=1400`） |
| 生成最终答案 | 未执行 |
| 第二轮规划 | 未执行（QP-1D 范围） |

### 执行缺陷（保留记录）

第一段把同一个 settlement admission 复用到整个 run，第 13 次起被逻辑配额拒绝
（`AdmissionRefused: budget_exhausted`），因此只完成 6 题 × 2 组 = 12 次真实发送。
第二段改为**每次操作独立 admission**（`scope_id` 含题与组），补跑剩余 4 题 × 2 组 = 8 次。
合计 20 次，未超授权；被拒绝的 8 次没有产生发送或费用。

## 方法

| 组 | 查询来源 | 模型调用 |
| --- | --- | --- |
| A | 用户原始整句 | 0 |
| B | QP-1B 之前的 `interpret()` 指令（`BASELINE_INSTRUCTION`） | 1/题 |
| C | QP-1B 之后的 `interpret()` 指令（当前生产） | 1/题 |

三组固定同一提供商（`auto` = SearXNG/bing）、同一 `max_results=6`；B/C 只取前两条规划查询。
每题、每组单独搜索，`DirectHit@6` 与 `MRR@6` 只用第一条查询；第二条查询的累计相关数单列。
不生成答案、不做第二轮规划。

可核实的差别：

- C 组**不再生成强制的 `site:` 查询**；B 组在 A01 生成的那条 site: 查询实测返回 **0 条结果**；
- C 组更常保留「当期 / 上半 / 下半 / 敌人机制 / 增益」等时点与任务焦点；
- 实体保留率：B = 0.9，C = 0.9（10 题中至少一条查询保留实体锚点）。

## 检索结果（固定 SearXNG/bing，top 6）

| 组 | DirectHit@6 | 平均 MRR@6 | 累计相关条数（≤2 查询） |
| --- | ---: | ---: | ---: |
| A 原始整句 | 1/10 | 0.10 | 3 |
| B 旧指令 | 1/10 | 0.10 | 4 |
| C QP-1B | 1/10 | 0.10 | 4 |

三组在该提供商上**没有可区分差异**：B01/B02/C01/D01 无论用哪组查询，返回的仍是
`星_百度百科`、`汉语查`、`千问`、`云·星穹铁道` 等同一批页面。查询已经带上正确实体与意图，
但该提供商看起来只匹配到第一个词。

对照 `SEARCH_TO_ANSWER_BASELINE_1.md`：同样的问题用 DuckDuckGo 可以拿到米游社、17173 等攻略。
因此本轮瓶颈指向**提供商相关性/路由**，而不是查询文本。

## 结论（限定范围）

> 在本轮 10 题、固定 SearXNG/bing 提供商、单次采样条件下，查询规划改进**没有**提升相关检索命中率。

这支持下一步验证提供商选择与相关性路由；它**不**证明所有游戏搜索都应永久优先 DDG，
也不证明 Bing 只能识别第一个词（本轮未做单提供商参数化对照）。

## 限制

- 10 题、单次采样；DDG 未参与（避免突发限流破坏 A/B/C 的公平比较）。
- 自动相关性判据是关键词匹配，**对英文查询系统性不利**（A05/B05/C04 的 C 组英文查询被低估）；
  人工抽查确认 Bing 返回的确为无关页面。本文件不把该判据称为语义正确率。
- 20 次预算已用满，复跑需重新授权。
- 原始产物：`docs/research_quality/QP1C_QUERY_PLANNING_AB.final.json`（合并结果）、
  `.json` / `.part2.json`（两段原始记录）、`search-results.md`（按查询重放的 top-6）。
