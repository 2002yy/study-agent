## 结论（下一批依据）

1. **正文**：7 个平台中 5 个可直接读到；NGA 需要一次站内跳转跟进（已实现），小红书需要登录入口。
2. **讨论**：评论/回答/回复确实在 DOM 中，但每个平台的容器、展开与分页不同。不做“最长容器就是正文”的统一猜测，按平台抽取，且必须区分“读到正文”与“读完整讨论”。
3. **视频**：公开字幕不可依赖（B站只有弹幕，YouTube 本次不可达）。可靠路线是 `yt-dlp` 取音频 → `ffmpeg` 转码 → `whisper.cpp`/SenseVoice 本地转写；评论走平台公开 API 并限制页数；关键帧后续用 `ffmpeg` 抽取。
4. **边界**：不绕过登录、验证码或付费墙；正文读取失败必须把登录墙、验证墙、超时、无正文分开返回。

## 讨论读取（2026-11-25，通用规则，不做平台系统）

实现：`web_read` 的 `include_discussion` + `max_comments`，复用同一次浏览器导航；
正文与讨论分开返回，并带 `discussion_scope`（页、条数、`may_be_partial`）与 `next_url`。

| 平台 | 实测 | 结论 |
| --- | --- | --- |
| V2EX | 4.2 s，5 条真实回复，作者/时间部分可得，`next_url` 指向 `?p=2` | 可用；分页交给模型决定 |
| 米游社 | 正文可读；评论在 DOM 中，但通用“叶子”规则抓到作者/位置碎片（如“社会奇迹 来自内蒙古”） | 需要一条平台选择器，下一片补 |

过滤规则（通用）：去掉正文自身、纯数字/翻页控件、“N 条回复 • 时间”、“只看楼主/排序”等 UI 行；
连续重复行合并；作者与时间从条目头部剥离。没有为平台写独立读取系统。
