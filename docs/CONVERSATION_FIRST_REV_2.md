## 0. 结论

结构调整（对话正文为主、研究降噪）方向正确并保留。当前问题：界面干净但偏空、偏呆板，缺少对话节奏/内容层次/持续研究感。
**不推倒重做**，只做一轮有边界的体验精修。

## 1. P0 — 正确性与上下文（优先于视觉）

### P0-1 研究状态必须绑定到具体消息，而不是全局横幅
- 现状：流萤/围棋顶部都显示 `研究已结束，仍有待确认问题 · 深入研究记录已审计，候选内容尚未获准发布`，即使任务是“从零教我围棋”。
- 规则：
  - 普通聊天 / 已有知识教学 → **不出现**研究横幅。
  - 正在联网 → 在**当前助手消息附近**显示一条轻量状态。
  - 研究完成 → 状态自然收起，引用留在回答中。
  - Deep 审计未获批准 → 只说明该部分不能作为正式结论，**不覆盖**整段教学体验。
- 现状成因：`ResearchWorkspace` 作为 `.research-status-row` 挂在会话顶部，未与 `turnId` 语义绑定；需改为挂在该条助手消息上下文中。

### P0-2 疑似演示来源冒充实际研究来源
- 围棋正文只是布局示意，却出现 `查看 来源 1`（`example.com`）。正式视觉验收不得用占位来源冒充研究依据。
- 规则：示范/占位内容不得渲染 `来源 N` 引用与可点来源；或明确标注“演示占位”。

### P0-3 用户消息被裁剪/滚动隐藏
- 流萤截图里用户消息只剩一条浅蓝色条状区域。
- 需检查初始滚动位置与消息容器裁剪，保证用户上下文可读。

## 2. P1 — 视觉精修（一次性完成，不再重排布局）

### P1-1 头像（用户已冻结决策，取代上一轮“缩小到 28–36px”）
> **保留原版大角色头像，将其从正文上方移至正文左侧留白区；正文宽度（760–820px）与居中阅读轴线不变。桌面优先展示完整角色形象，移动端响应式调整。**
- 大头像放到对话正文**左侧留白**，不挤压正文。
- 头像顶部与助手回答起始位置对齐；随该条助手消息滚动，不悬浮固定。
- 同一条助手消息**只出现一次**大头像，不在每一段重复。
- 手机 390px：头像回到消息顶部/左上，适度缩小避免压缩文字。
- 正式角色头像必须出现（现预览里是灰圆 —— 那是 `e2e/api-fixture.ts:489` 的灰圆 SVG stub，非产品缺陷；但视觉验收需用真实头像）。
- 四个角色头像视为 Study Agent 相对普通 ChatGPT 的特色，不抹平。

### P1-2 重复标题 / 左栏空间
- 左栏与主区都写“学习工作台” → 主区改为当前会话标题（如“流萤：版本配队研究”）。
- 左侧会话列表太松 → 收紧纵向间距，不强行填满。

### P1-3 “学习状态”入口
- 现状像独立工具栏 → 改为小入口，展开才显示学习目标、掌握情况、下一步。

### P1-4 输入框比例
- 空输入状态更紧凑；随行数自动增高；长回答滚动时底部保持可用；键盘打开后当前消息末尾可见；“对话/搜索”不必始终最醒目。

### P1-5 对比度与次级信息
- 正文正常深色；灰蓝小字提高对比度；来源用可读名称而非裸 URL / `example.com` 占位。
- “证据轨迹”与正文绑定：来源引用与对应段落关联，详细轨迹作次级入口。

### P1-6 手机研究抽屉
- 默认先展示“资料来源”和“尚待核实的问题”；技术细节（Lookup/Standard/Deep、版本、更新时间的读取计数）走独立折叠。
- 增强遮罩层次；固定抽屉标题与关闭按钮；内部滚动不把关闭按钮/资料导航推走。

## 3. 内容节奏（P1，非纯 CSS）

ChatGPT 式体验的关键是**回答如何被组织**：先给判断 → 解释原因 → 展开依据与条件 → 给下一步。
- 围棋示例：`围棋入门，先不背定式。先学会怎么吃掉对方棋子 → 解释“气” → 交互棋盘试一手 → 解释为什么先学吃子 → 继续`。
- 流萤示例：先给判断 → 解释协同机制 → 嵌入角色比较/版本时间线/伤害条件。
- 交互组件只在真正帮助理解时出现。

## 4. 下一刀执行顺序

1. **P0**：研究状态绑定消息；用户问题不被裁剪；演示来源不得冒充研究来源。（正确性优先）
2. **P1**：一次性视觉精修（头像左移、去重复标题、行距/对比度、手机抽屉、输入框）。
3. **真实长内容验收**：流萤多版本比较 + 机制理由 + 引用；围棋一次完整解释 + 交互练习 + 反馈；观察真实滚动/逐段呈现/资料定位。

## 4.1 P0-1 冻结原则（授权开工时确认）

> **只改变研究状态的呈现位置，不改变研究状态的权威来源。**

- 用服务端 `turn_id / run_id` 关系绑定研究进度；**不得**根据“当前最后一条助手消息”推断归属。
- 普通聊天与围棋教学：**没有对应研究运行就不显示**研究状态。
- Lookup / Standard / Deep 属同一问题时聚合在该助手消息下，不再显示会话级横幅。
- 迟到 SSE / 刷新恢复 / 后台 Deep child 完成，**不得**把旧研究状态附到新消息上。
- 若现有协议无法可靠确定消息归属：保留安全的会话级入口或隐藏有歧义细节；**不捏造关联，不修改 RP-1 后端协议**。
- 保留已冻结的 `0` 与“未知”的区别，以及 Deep-4B 发布权限边界。

### 实现设计（P0-1）
- 把 `ResearchWorkspace` 拆成两部分：**（a）绑定到具体助手消息的轻量状态行**；**（b）面板级侧栏/抽屉**（供资料详情，`open` 状态在 ChatPanel 层）。
- 状态行渲染进**匹配 `turnId` 的那条助手消息块内**；面板/抽屉仍在 `conversation-shell` 层，避免把侧栏塞进消息。
- 归属判定继续走现有 `research-presentation?turn_id=...`（服务端返回的快照校验 `session_id`/`turn_id`）；无对应 run → 状态行与入口都不渲染。
