## Lookup保持快速查证定位

默认保留30秒、10秒收尾预留、2次搜索、3次读取（两次基础+一次恢复）、
单源6000与总量16000字符。40秒/3 searches/4 reads与候选8仅为实验档。
优先测首次有效来源命中率，改善可信官方地址/精确官方搜索、去重与有效读取率。
第三次读取用于错误首页/重定向/错版本、身份有效但字段截断、尚未尝试的精确官方候选；
不能靠额外Lookup读取吞掉复杂比较任务。

简单事实有合格证据则VERIFIED；可靠相关来源仍有可验证未解决主张才考虑Standard。
提供商失败、模型格式失败如实记技术阻断，不伪装成Deep证据缺口。
扩展的是可验证问题计划与路由域覆盖，不降低身份/版本/span/hash门槛。

未来变更必须同时核对RecoveryBudget、lookup_terminal预算事实检查、父子截止时间，
区分recovery_budget的恢复模式与正式Lookup→Standard→Deep运行状态。
R6c后另预登记10–20个Lookup来源类型样本：首次有效来源、尝试/有效读取数、
停止原因、时延和升级状态；本轮不扩充这一样本集。

## 研究深度与教学方式独立路由

不因“讲得详细”、课程长短或用户热情自动升级Deep；研究层由证据复杂度决定。
研究维度：无需联网 / Lookup事实核验 / Standard多来源条件比较 / Deep系统证据研究。
教学维度：直接解释 / 引导练习与纠错 / 长期课程与恢复。
研究产物不直接证明学习掌握，也不自行授予发布/learning写入权威。

拟登记服务端任务合同字段（目前不修改生产数据模型）：

| 字段 | 方向 |
| --- | --- |
| research_intent | 事实查询、攻略比较、跨版本研究、技能教学、局面分析 |
| version_scope | 当前、历史、明确版本区间；版本是证据身份 |
| teaching_mode | 直接回答、引导练习、长期课程 |
| tool_requirement | 计算器、互动棋盘、棋力引擎、战斗模拟等，经工具能力资格化 |
| evidence_policy | 按领域约束来源类型、适用条件、版本/跨度/内容哈希及可复现计算 |

模型只提出建议，服务端决定资格、执行配额和权限；增量合同与Learning State-1独立审查。

机制理由、实战证据和版本差异”，预期Deep研究，输出可直接解释或转教学。

基础机制/精确技能数据应由Lookup核验；有持有角色与资源约束的配队取舍优先Standard。

### 2026-10-09 产品验收边界补充

RP-1 的技术网站样本只能证明研究基础设施，不证明优秀攻略分析或教学能力。
当前实际顺序是 S3 引用表达（本地已关闭，原因为缺少合格ref，并非引用丢失）

发布/语义与覆盖门未通过则保持 NO-GO。以下集合独立于冻结 R6，暂不施工或扩样本。

| 独立产品样本 | 验收目标 |
| --- | --- |
| G1 指定版本流萤配队 | 明确实际验收版本、投入档位、队伍与机制理由 |
| G2 跨版本完整攻略 | 历史可用角色/装备不串版本，解释阵容演变及证据限制 |
| G3 缺少角色下的替换 | 按用户持有角色给出替代、机会成本与适用条件 |
| G4 攻略观点冲突 | 区分条件、来源和测试口径，不把共识或排名等同事实 |
| W1 围棋规则入门 | 规则解释正确，互动棋盘校验合法落子/气/提子/劫 |
| W2 吃子与死活练习 | 验证用户落子，解释错误与局面；未验证不标记掌握 |
| W3 常见定式 | 讲清变化与适用条件；必要时另资格化棋谱/棋力引擎 |
| W4 多轮课程恢复 | 恢复真实课程/作答状态及下一练习，不把听过等同学会 |

游戏证据另分官方数据、可复现计算、配置/敌人/环境明确的实战验证、社区观点。
