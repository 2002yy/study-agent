## 1. 代码级梳理：可复用 vs 缺口

### 1.1 可直接复用（**不**重造研究框架）

| 能力 | 现有实现 | 复用方式 |
| --- | --- | --- |
| 持久 run + 检查点 | `WebLookupRepository.checkpoint(...)` 已持久化 `research_context`（plan/notes/steps/steering/computations/incremental_budget）、`query_attempts`、`selected_sources`、`rejected_sources`、`items`、`warnings`、`stop_reason` | 恢复所需研究事实已在库中 |
| run 级操作获取 | `WebLookupRepository.begin_operation(run_id, …, stale_after_seconds=120)`（原子获取 + 陈旧回收）与只读视图 `operation_is_stale` | 作为执行权基础，**但需租约续期**（见 §2.6） |
| 协作式取消 | 执行器 `ensure_active()` 逐步检查；`cancel_requested/finish_cancel`；`cancel_owned_by_turn(turn_id)` | 显式“停止”立即取消 |

| 陈旧操作回收 | `RuntimeRepository.recover_stale_operations(...)` | 进程重启后回收未结算 operation |
| 转向/预算/计算 | `steering_plan`、`incremental_budget`（grant 幂等、consumed 不复位）、`computation_step` + 工具注册表 | 原样保留 |
| 费用拦截单点 | `llm_client` 的统一构建点 + `attachment_vision` 的预留 | 保留单点，改为**持久账本**（§3.2） |

### 1.2 缺口

| # | 缺口 | 事实 |
| --- | --- | --- |
| G1 | 执行与 HTTP/SSE 耦合 | 准备阶段同步执行；断开 → `cancel_owned_by_turn` |
| G2 | 无长任务授权概念 | 只有“本轮对话”；**默认关闭**是本设计的起点 |
| G3 | 费用账本进程级 | `llm_spend_guard` 预留额在内存，重启归零 |
| G4 | 现有“执行身份”不等于长任务租约 | `begin_operation` 的陈旧判断基于**操作开始时间**（默认 120 s）；长读取会被误判陈旧，且需保证失去租约的旧执行者**无法回写** |
| G5 | UI 无断线重连与异步状态 | 只按 SSE 渲染 |

| G8 | 检查点 ≠ 外部操作恰好一次 | 崩溃可能发生在“网页读取/付费调用成功”之后、“结果落库”之前 |

## 2. 冻结设计契约

### 2.1 运行生命周期：run 与连接解耦

- 研究由**后台 worker**推进；HTTP/SSE 降级为**只读观察者**。
- 进入方式：交互式创建（即时观察）、断线后重连观察、重启后由调度器发现并继续。
- 执行仍由 `WebLookupService` 的既有执行/续跑路径完成，调度器只**唤醒**。

### 2.2 长任务授权（默认关闭）

- 长任务**不默认开启**；用户在确认界面显式选择「后台深度研究」。
- 授权界面（示意，非现有控件）：

```
后台深度研究
离开页面后仍可继续研究；达到任一预算上限即暂停。

最长持续时间   15 分钟
最高预留费用   ¥10
模型调用总量   24 次（其中视觉最多 2 次）
网络资源       搜索 20 次 / 读取 30 次
```

- **15 分钟是绝对期限**，自**用户授权时刻**起算；重启、重连、恢复都**不**刷新。
- 用户可下调额度；如需更高额度或暂停后继续，必须**再次明确授权**，Agent 不得自行增加预算。

### 2.3 持久恢复与“恰好一次”的严格表述

- 恢复依据：`query_attempts`（已完成搜索）、`selected_sources` + notes（已读正文）、
  `deep.plan/steps/round_index`、`steering[k].executed_in_round is None`（未执行转向）、
  `computations[k].input_revision/status`（计算版本）、`incremental_budget`（预算）、
  以及该 run 的**持久费用预留**（§3.2）。
- **已提交（committed）的结果不重复执行**：以库中的 `query_attempts`/`selected_sources`/
  `computations` 为事实，仅补齐 `status == "pending"` 的计划任务与 `executed_in_round is None` 的转向。
- **不做绝对“恰好一次”承诺**：对**结果不确定**的外部操作（调用可能已成功但未落库），
  按 §2.7 的对账/安全恢复处理；宁可**如实报告不确定**，也不重复承诺已完成事实。
- 恢复**不重置** `incremental_budget.consumed`，也不重新发放初始额度。

### 2.4 `paused` 是持久状态，`waiting` 只是显示

| 状态 | 含义 | 可恢复 |
| --- | --- | --- |
| `paused` | 持久、**仍有未完成工作但没有执行授权**（边界耗尽或等待再次授权）；进入后**不继续付费** | ✅ 经再次授权 |
| `waiting` | **显示层**状态（排队等待 worker、等待用户授权），**不写数据库** | — |
| `partial` | 已有部分结果；**不据此宣称异步任务已完成** | ✅ |
| `cancelled` | 用户显式终止的终态；**普通自动恢复不得重新激活** | ❌（仅显式重新创建） |

- **取消优先于既有 retry**：`begin_operation` 目前允许重新接管某些 `cancelled` run；异步模式必须
  增加限制——用户明确停止过的事实不得被普通恢复清除，也不得因此重新发起付费执行（N13）。

### 2.5 UI：断线重连与真实状态

- 重连：按 run 身份取回进度与最近的 steering/computation 事件（扩展既有
  `GET /sessions/{id}/research-queue` 思路）。
- 断线后必须能显示「仍在进行 / 已暂停 / 已完成的部分」，而不是清空成“未开始”。
- 展示状态映射自持久事实：`running`（搜索/读取中）、`waiting`（等待 worker/授权）、
  `paused`、`partial`、`completed`、`failed`、`cancelled`。

### 2.6 安全与并发：租约 + 心跳

- **同一 run 只能有一个执行者**：以 `begin_operation` 的原子获取为门；异步执行必须：
  1. 获取租约成功才推进；
  2. **心跳/续期**，使长时间读取不会被误判陈旧（现有 120 s 时间判断不足）；
  3. **失去租约的旧执行者不得回写**（写入必须带租约/版本校验；`begin_operation` 已有
     “不允许陈旧所有者回写”的语义，异步模式要把租约续期接上）。
- 进程重启：`recover_stale_operations` 回收后才允许重新接管。
- 取消：任何时刻的显式停止写入取消事实，执行器下一步 `ensure_active()` 退出，且**不再发起付费调用**。

### 2.7 调度：为普通长任务新增**受限**发现规则（G7）

- **不把** `DeepTriggerRepository.discover()` 当作通用研究队列：它服务 ARM→PENDING→PUBLICATION
  （Standard→Deep 交接与发布），必须保持其语义与顺序不被长任务挤占。
- 新增一个**独立、受限**的异步研究发现入口：只发现**具备显式长任务授权、状态为 `paused`
  或 `running` 且租约可用**的 `WebLookupRun`；与既有 ARM/PENDING 扫描**互不阻塞**
  （各自配额、各自分页），避免一个长任务阻塞 Standard→Deep 交接。
- 发现即可恢复；恢复条件与 §2.3 一致。

### 2.8 不确定结果的安全恢复（G8）

- 对“调用可能成功但未落库”的操作（网页读取、付费模型调用、计算），恢复时：
  1. 先**核对**是否已有对应提交（幂等键：`query_attempts`/`selected_sources`+url/`computations.input_revision`
     /费用 `call_id`）；
  2. 无对应提交时，按**有界重试**重新执行或**如实标记不确定**；
  3. **绝不**把未确认的结果写成“已完成事实”。
- 该语义覆盖：进程崩溃、超时中断、旧租约被回收。

## 3. 两条硬约束

### 3.1 断线 ≠ 取消，也 ≠ 无限授权

| 事件 | 即时交互模式 | 长任务模式（显式授权） |
| --- | --- | --- |
| 连接关闭 | **取消**（保持现状；已有回归 `tests/test_stream_disconnect_cancels_research.py`） | **不取消**：转后台，受绝对期限/调用次数/费用三重边界约束 |
| 显式“停止” | 立即取消 | 立即取消（最高优先） |
| 服务器重启 | — | 调度器发现并**恢复**；租约回收后才接管 |

### 3.2 费用账本：持久化 + run 级与全局账户级两层

**作用域**：主作用域 = `run`（turn 太短、session 太宽；run 与研究任务持久身份一致）；
**另设账户级全局上限**，因为多个并发 run 各自 ¥10 仍可能超出账户允许总额。

**权威公式（修订）**：

```
剩余额度 = 授权总额 − Σ(唯一调用的预留额)
```

- **同一 `call_id` 只有一份有效预留**；跨重启、超时、重试都保持该约束（幂等键）。
- **不自动退回不确定的预留**：实际消费**另行记录供审计**；保守策略下预留不退还。
  （原稿 “Σ(预留+结算)” 会把同一笔调用重复扣费，已更正。）
- **同一数据库事务内**同时核验 run 授权余额与账户全局余额；任一不足即**请求前拒绝**。
- **视觉调用**若发生在 run 创建前，必须绑定**同一授权 ID**，之后关联到 run，不得成为漏计入口。
- 恢复运行时读取既有预留，**不重置、不叠加新的 ¥10**。
- fail-closed：配置上限但缺价格 → 拒绝调用。

**token 上界重审**（实现阶段必须完成）：确认中文（CJK 按字计）、图片（base64/像素代理）、
多模态与 **SDK 自动重试**都被保守覆盖。**零额度拒绝只证明拦截动作有效**，不足以单独证明
“所有调用的费用估算都高于真实收费”，因此需要一次**估算 vs 实际**的对照记录。

## 5. 负控矩阵

| # | 负控 | 期望 |
| --- | --- | --- |
| N1 | 连接关闭（长任务模式） | run 继续，且不超过授权期限/调用数/费用 |
| N2 | 连接关闭（即时模式） | 保持现状：取消，不再发起付费调用 |
| N3 | 显式“停止” | 立即取消；取消后 0 付费调用 |
| N4 | 进程重启 | 调度器发现并恢复；**不重复**已提交搜索/读取 |
| N5 | 恢复时的费用 | 剩余额度取自持久账本；**不重新发放**授权额度 |
| N6 | 双执行者并发 | 第二执行者被租约拒绝（同一 run 不双跑） |

| N9 | 同一计算版本重复恢复 | 计算幂等，不重复执行 |
| N10 | 预算账本损坏/缺失 | fail-closed：暂停并如实报告，不默认无限 |
| **N11** | 研究超过租约陈旧阈值但原 worker 仍活着 | 第二执行者**不能接管**并双跑（心跳/续期生效） |
| **N12** | 外部调用完成、检查点提交前崩溃 | 对未确定结果**安全恢复/如实标记**，不重复承诺已完成事实 |
| **N13** | 用户取消后有人调用恢复接口 | **不得**清除取消事实并重新发起付费执行 |
| **N14** | 跨会话访问进度/重连端点 | 无权用户不能读取研究材料、费用或进度 |

## 6. 验收标准

### 6.1 两层验收

| 模式 | 标准 |
| --- | --- |
| **即时交互验收** | 300 s 内能启动研究、展示**真实**进度、接受补充、返回明确状态；**未完成不得谎称成功**。原 A 场景在此模式下的通过条件**仍按原标准** |
| **异步完整任务验收** | 在**用户批准**的总时间与费用上限内完成搜索→补查→重算→图表，且可从持久状态恢复、断线不丢、重启不重跑、费用不重发 |

### 6.2 Async Deep-1 独立验收门（原 A/B/C 不重新解释）

| 测试 | 必须验证 |
| --- | --- |
| 持续运行 | 断开前端，研究仍在授权范围内执行 |
| 重连 | 同一 run 恢复进度与已取得证据 |
| 服务重启 | 重建执行状态，已提交工作不重复 |
| 中途更正 | E1/S1 → E2/S5，必要补查及新计算 |
| 费用 | 恢复不重发额度，超额在请求前拒绝 |
| 显式停止 | 停止后不再发起新付费调用 |
| 最终结果 | 来源、计算、图表、状态、持久化记录一致 |

### 6.3 前置（免费）与真实模型

- **首轮真实模型验收前必须先完成 N1–N14 的零计费负控**（断线、重启、竞争执行者、账本）。
- 首轮真实授权申请候选：**15 分钟 / ¥10**（由用户批准；系统仅推荐）。
- 之后如需调整，依据**真实耗时数据**由用户决定，**不由模型自行修改门槛**。

## 8. 性能路线（单独冻结，**本文件不实施**）

**Reader Performance-1**（建议另立合同）优先级：

1. **先定位并限制慢读取**：分别记录 DNS、连接、下载、正文转换、各后备读取器的耗时，找出
   “单页 44 秒”的分布；为**失败后备链**设定时间与重试预算，避免单个无效来源阻塞整轮。
2. 再提高**来源选择质量**（候选优先级）。
3. 最后优化**已有证据复用**。

约束：**不能**一刀切把所有网页限制为 10 秒，否则会连带淘汰“慢但确实有效”的来源。
