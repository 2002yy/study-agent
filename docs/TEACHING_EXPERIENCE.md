## 用户入口

对话输入框底部的“选角色”按钮（选定后显示角色名）打开角色面板。
选择纳西妲、三月七、流萤或既有刻晴，从下一条回复生效；“自动”恢复路由选择。
切换不清空输入，不改历史消息角色，生成中不改当前轮角色。
学习方式仍在“设置与工具 → 设置 → 学习方式”，也可直接说“先让我猜”“我来讲，你检查”
或“完整讲解”。角色与学习方式互相独立。

## 三种声音

| 角色 | 观察角度与节奏 | 措辞参照（人工撰写，并非模型实测） |
| --- | --- | --- |
| 纳西妲 | 温和拆分关系、约束与边界；短句串起因果 | “先看谁拥有这份状态。每个玩家的血量可以不同，服务器人数却不能各记一份。” |
| 三月七 | 轻快、好奇，抓住反直觉；小吐槽立即落回机制 | “一千个玩家，一千份血量，没毛病。但服务器人数也让大家各记各的？” |
| 流萤 | 细致陪练，停在当前一步；温柔且明确纠错 | “先停在这一行。对象还在原处，变的是 b 里保存的引用。” |

不靠固定口头禅、舞台动作或机械表扬区分角色。流萤不再被核心定位局限在收尾陪伴。
三份 `roles/*.md` 的“11. 语言纹理”明确进入 `build_role_prompt()`；
旧“3. 教学风格”仍不进入单聊，避免其“先给答案/先问问题”与当前教学计划争夺顺序。
界面的角色说明与这些方向一致；详细规则只保留在角色文件里，不由 UI 复制到每轮提示。

## 三种方法怎样内化

- 第一性原理：共用讲解方法。拆目标、基本事实、状态归属、约束、执行顺序，再推导行为。
  不新增模式枚举；语言约定与外部事实直接提供，不要求学习者凭空推导。
- 苏格拉底：沿用有状态协议，一轮一个中心问题，预测、线索、反例逐步推进。
  提问后等待下一条用户消息，不在同一条回复或交互组件里揭底。
- 费曼：沿用解释—找一个主要缺口—最小修正—重新解释的循环。
  不要求完全没背景的人凭空复述，不将“懂了”视为掌握证据。

`src/pedagogy/teaching_style.py` 经 `build_system_prompt()` 接入实际模型消息；
它负责讲解形式，现有 `PedagogyTurnPlan` 负责本轮认知动作和披露程度。
新 `intent.py` 供路由、苏格拉底和费曼共同识别明确直答要求及邻近否定词。
修复费曼 repair 阶段仍强制复述，以及“不要直接回答”被当成直答的具体回归。
没有新模型调用、自动重试、文本过滤器、数据库字段或第二套教学调度器。

## 本轮最重要的教学约定

每课围绕 2～4 个核心问题，跨轮采用：
场景 → 问题 → 直觉 → 语法 → 执行图 → 脑内预测 → 误区 → 实际后端 → 简短总结。
这是组织参考，不能逐条照抄成一次性输出的九节教材。

从用户系统、订单、游戏服务器、库存、连接、缓存、Spring Service、并发请求取例。
`static` 从玩家各自的血量与服务器共享计数引入；`final` 区分引用重新赋值与对象内容改变。
引用/对象身份可以用 Student 保持模型一致。代码按状态变化逐步展示，例如：

```text
执行 new 之后：a → 对象① { name=null }
执行 b=a 之后：a → 对象① ← b
执行 b.name="Tom" 之后：a → 对象① { name="Tom" } ← b
```

上述是完整解释阶段的演示。如果正在让学习者预测第三行，就只展示前两步，然后等待。
一课分散安排 2～3 次互动，一次只问一个有关键转折的问题。回答后先回应实际推理，
再纠正或推进。学习者要直接答案或完整讲解时，立即解释，不强制互动。
中文术语优先，常用名称可以保留；类比必须注明与真实机制的对应及局限。
