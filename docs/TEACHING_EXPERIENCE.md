## 三种方法怎样内化

以下为用户于 2026-11-02 修正后的思想定义，替代此前把方法简化为教学操作的版本。
三者分别回答：如何从根本认识与重新推导、如何通过对话自主发现、如何透彻理解并简单表达。
它们可以配合，不是三套互相替代的讲课流程；现有模式仅表示侧重点，不新增模式枚举。

### 第一性原理：从根本出发，重新构建理解

不满足于现成定义、传统解释、经验结论或表层因果关系，而是不断追问事物最根本的事实、
规律、条件与必然性。**核心不是把问题拆细，而是找到无法再轻易简化的基础，并从这些基础重新推导。**

- **追溯根本**：为什么存在？要解决什么最根本的问题？有哪些无法绕开的事实与规律？
- **质疑前提**：哪些是客观限制，哪些只是习惯、约定、历史选择或未经证明的假设？
- **重新推导**：暂时放下现成答案，从基本事实推导机制、设计或结论，让每一步都有因果或逻辑依据。
- **发现新结论**：探索表面观察、直接分析或记忆现有知识难以发现的结论、可能性与局限。
- **检验与迁移**：用反例、边界条件和现实证据验证推导，并探索相同原理能否解释其他问题。

目标不是把已有答案解释得更复杂，而是能够独立重建答案，甚至发现新的答案。
拆状态归属、执行顺序或解释现成机制可以帮助分析，但本身并不等于第一性原理。

### 苏格拉底法：通过对话，引导自主思考与发现

借鉴苏格拉底的问答与诘问方式，通过有针对性、层层深入的对话，让学习者审视认识、发现矛盾、
修正判断并形成理解。**核心不是提问，而是让思考真正发生在学习者自己身上。**

- **从已有认识出发**：了解学习者如何理解问题，以及这种理解依赖什么前提。
- **通过追问深入**：追问为什么、依据是什么、是否一定如此、换一种情况还成立吗。
- **利用反例与矛盾**：以恰当的思想实验、反例或认知冲突，帮助学习者自行发现原有观点的不足。
- **循序引导而非代替思考**：根据回答动态调整问题，给予必要线索，不急于宣布标准答案。
- **共同澄清认识**：检验定义、前提和推理，形成更准确深入的理解，允许暂时没有确定答案。

不拘泥于固定问题数量，不把提问当考试；自然、开放地根据回答深入。

### 费曼学习法：用最简单的语言，讲透最深刻的道理

以能否向没有相关知识的孩子解释清楚为理解标准，使用直观语言、生活经验、具体情境和形象类比，
消除术语堆砌与抽象表达造成的障碍。**核心不是让解释变得浅显，而是让复杂知识真正可以理解。**

- **从直觉开始**：用生活现象、具体故事或简单实验建立直观认识。
- **用简单语言解释**：避免未经解释的专业术语，把抽象机制转化为容易想象的过程。
- **讲清楚为什么**：解释背后的因果关系，让每一步变化都有清晰理由。
- **检查理解缺口**：必须依赖大量术语才能说明时，继续拆解，找出尚未理解的部分。
- **由简入深**：逐步引入准确概念、术语、形式化表达与适用边界，避免类比产生误解。
- **能够独立讲明白**：不仅听得懂，还能用自己的语言清楚解释，并应用到新问题。

简单不是省略关键机制，通俗不意味着牺牲准确性。解释应在保持严谨的同时清楚易懂。
这不要求使用儿童口吻，也不要求每轮让学习者复述。

### 三种方法的协同

第一性原理负责深度，苏格拉底法负责主动性，费曼学习法负责清晰度。
根据知识特点和理解状态灵活使用，没有固定先后顺序，也不要求每节课全部使用。
第一性原理决定思考能深入到哪里，苏格拉底法决定什么时候由学习者主动探索，
费曼学习法决定知识如何被真正理解。

判断标准是学习者是否获得新的独立推理能力、理解现象背后的必然性，并能推导出此前不知道的结论；
不是提问、比喻和细节的数量。“提问、等待回答、定位缺口、重新讲解”不能成为强制流程。

### HashMap 推导参照（人工撰写，不是模型运行结果）

先放下 Java 和 HashMap。固定只有 10 个位置，却要存放 11 个不同的键，能保证各占一处吗？
如果学习者要自己探索，在这里等待并根据实际回答继续追问；完整讲解则可连贯推导：

1. 可用位置数量有限，而要区分的键比位置多。
2. 根据抽屉原理，至少两个键必须分到同一位置。
3. 因此只靠位置编号，无法永远唯一确定一个键；正确检索还需进一步区分它们。
4. 这推导出冲突与区分机制的必要性，尚未决定某个具体实现。

费曼式直觉可以是“10 个抽屉、11 双袜子，抽屉编号能帮你找到位置，不能保证里面只有目标那双”。
再回到桶、哈希值和键的相等性判断，区分真实机制与类比。Java 的实现属于设计选择，
不能由必要性直接推成唯一解；有限位置这个条件应说清，扩容或限制键集会改变具体场景。

### 实际接线与边界

`src/pedagogy/teaching_style.py` 经 `build_system_prompt()` 接入实际模型消息；
普通、苏格拉底、费曼与三个角色均接收这些共用思想方法。
现有 `PedagogyTurnPlan` 提供本轮侧重点及披露边界，侧重点不再限定“单一认知动作”。
费曼计划不按旧阶段强制复述、测试或仅凭长度/关键词宣告掌握；默认帮助重建理解，
只有现有评价器对当前输入、目标及协议给出的接受回执才能计划收束，ChatService 的证据门保持不变。
苏格拉底不再因问号超过一个判回复失败，问号计数仅留作观测；仍拒绝空回复和低披露时的提前揭底。
`intent.py` 继续识别直答及其否定，并供两个引导模式处理明确等待请求。
没有新模型调用、自动重试、文本过滤器、数据库字段或第二套教学调度器。

## 本轮最重要的教学约定

从场景与问题进入，按理解需要组合直觉、语法、执行图、推导、互动、实际后端与总结，
不强制顺序、互动次数或每轮问题数。已经理解则继续深入，缺背景先补知识，
实际发现缺口再针对性处理，不为了完成模板中断推导，也不倾倒几十节教材。

从用户系统、订单、游戏服务器、库存、连接、缓存、Spring Service、并发请求取例。
`static` 从玩家各自的血量与服务器共享计数引入；`final` 区分引用重新赋值与对象内容改变。
引用/对象身份可以用 Student 保持模型一致。代码按状态变化逐步展示，例如：

```text
执行 new 之后：a → 对象① { name=null }
执行 b=a 之后：a → 对象① ← b
执行 b.name="Tom" 之后：a → 对象① { name="Tom" } ← b
```

上述是完整解释阶段的演示。如果正在让学习者预测第三行，就只展示前两步，然后等待。
用户明确要求先想时，在关键结论前等待，不通过图表或按钮泄题；解释中的设问可以随即讲透。
自然邀请用户判断时留出作答空间；收到回答后回应实际推理，不预设其一定有错。
学习者要直接答案或完整讲解时，立即解释，不强制互动。
中文术语优先，常用名称可以保留；类比必须注明与真实机制的对应及局限。
