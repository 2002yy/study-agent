# 聊天图表设计准则

用户要求把 huashu-design 的部分设计方法内化到 Study Agent，让聊天图表有稳定的美学参考。
本轮沿用已选 A+C：白色对话区、鼠尾草绿强调、清楚的阅读层级。

2026-11-03 补充：自由 `interactive` 界面可由模型选择 HTML、SVG、Canvas 与交互逻辑，
内容优先、单位来源、说明与响应式准则继续由临时上下文传递。预设组件保持统一外观，
自由界面允许内容需要的布局和少量有含义的颜色；不强迫套固定模板。
执行隔离与状态追问协议见 [自由交互设计](INTERACTIVE_ANSWER_DESIGN.md)。

## 已接入的产品路径

`frontend/src/features/answer-ui/chatVisualDesign.ts` 保存精简准则，
`packAnswerUiContext()` 将其与现有组件格式一起装入临时 turn context；
`useLearningSessionRuntime` 已通过该函数构造聊天请求。
后端沿用现有临时上下文解包，不把准则写成用户长期偏好。
没有额外模型调用、设计评审回合或运行时 skill 文件依赖。

- 信息关系决定形式：分类比较用条形图，有序变化用折线图，精确查数用表格，数学关系用函数图。
- 结论先行，一图一个重点；名称、单位、来源、时间口径和假设需要可读。
- 只使用有依据的数据；示意在标题和正文同时标注，缺失值不能补成零。
- 配色与字号由现有组件统一；颜色不单独承担含义，保留数据表与文本复制。
- 不迁入三方向选稿、素材搜索、工作室分工和多轮审核流程，避免每次聊天增加等待。

`chart` 增加可选 `view: "bar" | "line"` 和 `unit`（1–20 字）；旧消息默认条形图。
2–40 个数据点及原有安全边界保持。未知样式和脚本字段不会进入渲染器。
条形图直接显示每个名称和数值，负值围绕共同零点绘制；折线画布在窄屏内横向滚动，
完整名称与数值保留在表格里。页面本身不横向溢出。

角色头像采用桌面 88px、手机 72px，使用原有 512px 纳西妲图片，
保留完整构图；头像作为消息署名，正文独占下一行，不挤窄长回复。
